## Проверка conversion tracking

Во время аудита была протестирована цепочка GA4/GTM для формы.

Подтверждено:

`Website form submission` -> `dataLayer event generate_lead` -> `GTM tag GA4 Event - generate_lead` -> `GA4 key event generate_lead`

До теста Google Ads показывал импортированную GA4-конверсию `Dapl Website (web) generate_lead` как incorrectly configured / never received data. После теста GA4 увидел событие `generate_lead`. Google Ads может обновлять статус конверсии несколько часов или до суток.

Текущий риск:

В аккаунте несколько действий-конверсий для лидов/звонков. Цель по телефону включает:

- `Dapl Website (web) phone_click`
- Calls from ads / звонки из объявлений
- Business Profile tracked call / отслеживаемый звонок из профиля компании

`phone_click` - это, скорее всего, клик по номеру на сайте, а не подтвержденный звонок. Его нельзя считать равноценным реальному звонку, если не проверяется длительность и качество звонка.

## Рекомендуемая настройка конверсий

Основные конверсии / Primary:

- `generate_lead` - успешная отправка формы
- реальные звонки из объявлений, желательно с минимальной длительностью звонка
- tracked calls из Business Profile, если это реальные звонки, а не просто клики

Вторичные конверсии / Secondary:

- `phone_click`
- `schedule_click`
- `book_online_click`
- другие engagement-события

Причина: PMax обучается на Primary conversions. Если мягкие клики стоят как Primary, кампания может оптимизироваться на клики, а не на реальные заявки.

## Рекомендация по структуре кампаний

Не стоит оставлять PMax единственной основной кампанией для этого бизнеса.

Рекомендуемая структура:

1. Запустить отдельную Search campaign на горячие локальные запросы.
2. PMax оставить как дополнительную кампанию с меньшим бюджетом после чистки exclusions и конверсий.
3. Разделить Search ad groups по услугам:
   - `Appliance repair Charlotte / near me`
   - `Refrigerator repair`
   - `Washer and dryer repair`
   - `Dishwasher repair`
   - `Oven / cooktop repair`
4. Ограничить гео только реальными зонами обслуживания.
5. Проверить location setting: нужны люди, которые находятся или регулярно бывают в целевых локациях, а не просто интересуются ими.
